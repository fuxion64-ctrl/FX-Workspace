# FX Workspace 1.5.0 - action plan (11 Nov 2026, for review)

How the approved 1.5.0 plan (`1.5.0.md`) gets built after 1.4.8, in what order, and what moved in. Each stage stops for your review. Nothing is built until you approve.

## What changed since the 1.5.0 plan was written

- **Done in 1.4.8, off the list:** the owner's 7 Nov notes - the setup wizard finishing its own work (Python, packages, the app repairing its setup on start) and adding a chat model with Browse…; plus choosing the models folder.
- **Moved in from 1.4.8 (your decision):** a one-call path for common PC questions (research A2) and llama.cpp's draft-free speculative decoding (A1).
- **Moved in from 1.5.1:** the Paper look (stage 5c said "1.5.0 if there's room"). It shares its whole build path with Glass - a /design board, a skin, the same checks - so doing both together costs less than twice. Recommended; your call.
- **Left over from 1.4.8's review, needing real models:** audit 2.3 (does the message check cost the prompt cache?), 2.6 (message order some chat templates reject), and item 5 (the tool-name line).

## Stage 0 - measure 1.4.8 on real models (High, ~1 session)

Everything in 1.4.8 was tested without a model. Before new features, prove the savings and catch regressions:
- Reply wall time and llama-server's own prompt tokens (read / reused - now in each reply's footer) on Qwen 3.5 4B and Ornith 9B: greeting, question, web question, PC action, Roblox action, a 10-turn chat. Same cases on 1.4.7 for the before.
- Tool-call validity on the benchmark, with and without the tool-name line (`FX_TOOL_NAME_LINE=0`) - decides item 5.
- Audit 2.3 and 2.6, per model family; fix 2.6 if a template rejects the order.
- Check by hand: the reply no longer erases its first sentences; a stuck-close recovery; setup on a PC without Python (a fresh Windows Sandbox).
- **Done when:** a numbers table in `docs/plans/1.5.0-stage0.md`, and anything that got worse is fixed or rolled back.

## Stage 8 - robustness carried over (High)

Smaller items from the 10 Nov audit that weren't in 1.4.8:
- Live stream and the turn long-poll without a request thread each (needs an async event hub; order, reconnect and keep-alive proven by tests).
- Background polls that stop when their page isn't showing (audit 3.4).
- A per-launch token so only the app's own window drives the API (audit 3.7, optional).
- The phone gets its own open chat (the per-client "turn object" from the chat-identity plan).
- The desktop shell: a hung (not exited) server is restarted; the mini window follows a port change (audit 3.2).
- "Loading … into memory" with an estimate, and one Models page for chat and picture models (`1.5.0.md` stage 6).
