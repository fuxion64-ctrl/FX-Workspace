# 1.4.6 stage 2 - tools: faster, and on by themselves (4 Nov 2026)

Measured on this PC (RTX 3060 Ti 8 GB) on the dev server, with real models: Qwen 3.5 4B (Q4_K_M) and Ornith 1.5 9B
(Q4_K_M). A small logging proxy sat between the app and llama.cpp, recording each model call: the tools sent and
llama.cpp's own timings (tokens read, tokens reused from its cache). Each case ran in a fresh temporary chat.
Approval cards were declined by the script. Single runs, so a few hundred ms either way is noise. Bonsai wasn't
measured: it needs PrismML's build, which restarts the router.

## How each change works for someone using the app

| You... | Before | Now |
|---|---|---|
| ask "write a Python function that ..." | Treated as an action: the model got run_python, often ran it "to test it", and you got an approval card for code you only asked to see. Qwen: 13.3 s, 8,239 tokens read | Written in the reply, no tools, no card. Qwen **6.9 s** (537 read), Ornith 8.5 → **5.1 s** |
| ask a quick question about the PC ("what's using my PC?", "list the files in ...") with effort on Auto | Auto picked High: a model-written plan and a model review around the answer | Auto picks Balanced for a one-step look (nothing changes): Qwen **15.2 → 5.2 s** and **8.2 → 3.3 s**. Changes and long requests stay High |
| start Tune speed, then want to chat | The chat waited (10-20 minutes in all), or found the model reloading with a setting being tried | It pauses between measurements while you chat, gives the model its own settings back, then carries on. A chat waits at most for the step in progress |
| watch a small model say "I'll now create the file" without doing it | Up to 2 retries asking in words; it often described the step again | The retry can only be a real tool call (llama.cpp `tool_choice: required`). Still goes through approval; "I'm finished" stays possible through update_plan |

Not changed, on purpose: "write a script for a kill brick", "write it to a file", "write it in my notes", anything with
Lua, Studio, a path or "send" stays an action.

## What was measured and dropped

- **Reading the prompt ahead while you type** (built and measured, then removed). Qwen's chat template puts the
  tool list first, so a new kind of message re-read everything: 3,500-3,800 tokens, about 2 s on the 4B. The read-ahead
  fixed the first call (3,830 → 628 tokens), but llama.cpp's own prompt cache already keeps earlier starts. In
  repeated runs the replies were no faster (PC question 10.9-13.2 s cold vs 10.9-11.0 s read ahead; numbers slightly
  slower), and on Ornith there was no change at all. Kept out: the plan's rule is "kept only if measured faster".
- **A fixed tool order** is kept: the three web tools nearly every turn has come first, use_tools last. Cheap, and it
  lets different kinds of message share the start of the tool list. On its own it saves little, because the system
  prompt comes after the tools.

## Already true (checked, no change needed)

- Image, Visuals, Charts and web search turn on by themselves (auto_tools, image_gen.wants_image).
- PC and app control safety levels exist in permissions.py: looking (open an app, read the screen or a window,
  list processes) runs without asking; typing and clicking in another app ask; closing, deleting, sending and running
  code always ask, and an override can tighten any of them.

## Found along the way (for the suggestions list)

- An approval while the app window isn't focused goes to a **native Windows popup**, which Stop doesn't close. The
  turn then sat for 10 minutes, and only a server restart cleared it.
- Every turn makes a small extra classifier call (~0.2 s, "Message to screen"). Cheap; left as is.

## Numbers (before → after, wall time per reply)

Qwen 3.5 4B (its effort pinned to High in the dev settings): chat 3.0 → 2.9 s, explain 4.8 → 4.7, numbers 7.7 →
7.7, PC question 15.2 → 18.2 (same High plan and review; the extra second is a 4th model step), files 8.2 → 8.4,
code 13.3 → 6.9. With Auto: PC question 5.2 s, files 3.3 s.
Ornith 9B (pinned to Balanced): chat 2.1 → 2.2, explain 4.6 → 4.1, numbers 3.7 → 3.7, PC question 14.1 → 14.2,
files 2.7 → 2.9, code 8.5 → 5.1.
