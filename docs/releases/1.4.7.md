# FX Workspace 1.4.7 - a checkpoint

**A checkpoint: a base version where everything should work.** 1.4.7 fixes the technical bugs and reliability problems found in real use, so the app keeps working instead of stopping at an error - and when something does go wrong, it says what and offers the fix that helps. New features build on this from 1.5.0.

It also brings everything from 1.4.6 (the redrawn looks, Settings in nine pages, faster tool replies, the new license), which wasn't published on its own - see [the 1.4.6 notes](1.4.6.md).

**Updating:** from 1.4.2 or later, Settings › About › **Check now** › **Update now**, or press **Update** on Home when it offers one. From older versions, run `FX-Workspace-Setup-1.4.7.exe` over them. Your chats, settings, keys and models stay as they are.

## Fixed

- **A model that can't load says why:** its file is missing, there isn't enough free RAM, or there isn't enough GPU memory, each with the button that helps. It no longer guesses "not enough GPU memory" when the real cause is a file that was moved.
- **Run on RAM too works.** It used to say "That didn't work" every time.
- **llama-server starts again by itself** when it stops or hangs, even in the middle of a reply. Try again then works straight away, and no message tells you to check run.bat any more.
- **Another program on one of the app's ports no longer breaks it.** The app, llama-server, the image engine, voice, music, the assistant's browser and phone access each move to a free port, and the desktop app follows them. Starting the app twice opens the one that's running.
- **If the app's server stops, the desktop app starts it again** and reloads the page.
- **A message too long for the model** is left out with a clear note, so the chat goes on. Before, it blocked every message after it.
- **A stuck llama-server no longer makes a reply wait minutes** before it is restarted (a "hi" took over 5 minutes in testing; now about 30 seconds, loading the model included).

## Models

- **Models whose file is gone are marked in the model menu,** with Find (looks for the file elsewhere on your PC) and Remove (takes it off the list; no file is deleted). Auto never picks them.
- **Not enough free RAM for a big model?** It loads from disk instead, so it still answers (the first reply is slower).
- **A model that overflows the GPU** and runs slowly is offered Run on RAM too.
- **Your own names for models:** the model menu, the model button, the sidebar and Images show the names you give them. Settings still shows the full name.
- **Images' filter chips list only the models on this PC,** not the whole original pack.

## Pictures

- **A picture shows in the chat the moment it's made,** without waiting for the chat model to load again.
- **A request that only asks for a picture ends right there.** The model no longer goes looking for the picture on your disk, which made chats "too long" and slow models time out.
- If something goes wrong after the picture is made, the picture stays in the chat.
- **Pictures from the web show in the chat:** ask "show me pictures of ..." and the app shows the main pictures from the web pages it finds, with the site each one came from. They're real pictures, not made ones.
- **Each picture shows its model and the styles its prompt asked for,** such as Photo, Anime, 3D render or Pixel art.
- **The Creating image card no longer blinks:** it updates in place while the picture draws.

## Chat speed and looks

- **Live reply speed is in tokens per second (tok/s),** counted as the reply streams. A speed that is estimated is marked with ~.
- **Smoother toggles:** a switch slides to its new position before the page saves and redraws, so it no longer jumps, and its curves are softer.

## Better error messages

- Each problem gets its own message and buttons: the model's file is missing, not enough RAM, not enough GPU memory, llama-server restarted, the chat is too long, the model took too long. The generic "Something went wrong" is now only for errors nobody could read, with the details one click away.
- **The voice page no longer tells you to run run.bat.** A missing voice package is installed again when you restart the app.
- A hard crash leaves a record in data\logs\crash.log, so it can be found and fixed.

## Known issues

- On some NVIDIA setups a model too big for the GPU doesn't fail but runs slowly from shared memory; the app now offers Run on RAM too when it sees that.
- Bonsai wasn't measured for the speed changes (it needs its own llama.cpp build).
